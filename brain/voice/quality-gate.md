Every asset must pass this gate before publishing. If any item fails, fix it first.

- [ ] Concrete, numeric opening — a specific claim with a number, not a generic lead.
- [ ] At least one anti-hype "when this does NOT serve you" section.
- [ ] For paid/extended assets: a dedicated anti-hype self-selection section up front (reader categories this is overkill for, with a concrete reason each), so the wrong reader opts out before buying.
- [ ] At least 3 documented anti-patterns, each with its consequence.
- [ ] Every number substantiated with transparent math (where it comes from, shown).
- [ ] An honest, non-sentimental close that hands judgment back to the reader.
- [ ] No word from the avoid-list (best practices, leverage, unlock, secret sauce, game-changer, guru, etc.).
- [ ] Consistent tone between narrative and analytical passages.
- [ ] For assets with a technical configuration: no tool marketing, an explicit cost/variance disclaimer, and explicit permission to experiment (your config framed as "what I used," never "optimal").
- [ ] If bilingual: both versions checked for natural style, not translation.
- [ ] No identifying private specifics (real names, stack, project, accounts) anywhere in the published files.
